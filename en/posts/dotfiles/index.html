My Dotfiles: A DevOps-Focused Development Environment

How I manage my dotfiles with chezmoi, the toolchain I've settled on, and how herdr became the place where my coding agents live.

Managing a development environment across machines is a solved problem — if you’re willing to invest a little upfront. This post walks through how I manage my dotfiles using chezmoi, the opinionated toolchain I’ve settled on, and how I replaced my terminal multiplexer with herdr, a multiplexer built around coding agents.

Why chezmoi?#

Dotfiles managers come in many flavors: bare git repos, GNU Stow, custom shell scripts. I landed on chezmoi for a few reasons:

  • Templating: a single dot_gitconfig.tmpl can render different values per machine (work email vs. personal email) using Go templates. The values live in ~/.config/chezmoi/chezmoi.toml, outside the repo, with sane fallbacks hardcoded in the template.
  • No symlinks: chezmoi copies files to their destination, so you’re never one rm away from a broken config.
  • First-class secrets support: integrates with password managers, age encryption, and environment variables.
  • Single binary: no Ruby, no Python, no system dependencies — just one binary managed by mise.

Bootstrapping a new machine#

Everything starts with one script — a gist — that handles:

  • Installing base system packages
  • Setting up Docker
  • Installing FiraCode Nerd Font
  • Installing mise
  • Setting Fish as the default shell

Then a reboot, and:

mise x chezmoi -- chezmoi init --apply thewalterman
mise install
nvim   # let lazy.nvim install plugins

From zero to productive in a handful of commands.

The toolchain#

mise: one tool to rule them all#

Instead of managing Node via nvm, Python via pyenv, and so on, I use mise. A single config.toml declares everything:

  • Kubernetes/DevOps: kubectl, helm, k9s, flux2, k3d
  • Editor: neovim
  • Productivity: lazygit, lazydocker, yazi, herdr
  • Shell: starship, fzf, zoxide, navi, eza, bat, fd, ripgrep

Everything tracks latest. I gave up on pinning personal tooling: a mise run full-upgrade task (mise self-update -y && mise upgrade) brings the whole box forward in one go. The same file also sets EDITOR/KUBE_EDITOR to nvim.

Fish shell + starship#

Fish gives me autosuggestions and syntax highlighting out of the box. I lean heavily on abbr (abbreviations) rather than aliases — they expand inline so you always see the full command before it runs.

Plain aliases are reserved for straight replacements: cat → bat -pp, ls → eza --icons, grep → rg -i. The init chain at the bottom of config.fish is mise → starship → fzf → zoxide (taking over cd) → navi widget. A few custom functions round it out: y (yazi that changes the shell’s directory on exit), fcd (fzf directory picker with an eza preview), fkube and fssh.

For the prompt I use starship, configured entirely through dot_config/starship.toml. It runs identically in Fish and Bash, and I use the right-hand prompt slot to show the current Kubernetes context.

Neovim (LazyVim)#

I use LazyVim as a base and add a small set of plugins on top:

  • bufferline — tab-like buffer navigation with Shift+arrows
  • smart-splits — pane navigation with Alt+arrows
  • nvim-spider — smarter w/b/e motions that respect camelCase and underscores
  • nvim-numbertoggle — relative numbers in normal mode, absolute in insert mode
  • herdr-nvim — the Neovim half of the herdr integration (more below)

navi#

navi is an interactive cheatsheet tool — hit a keybinding, fuzzy-search a cheat, fill in the placeholders, and it drops the finished command on your prompt instead of running it blind. It’s wired into Fish via navi widget fish, bound to the usual Ctrl+G.

The cheatsheets live in dot_config/navi/cheats/ and cover the commands I’d otherwise have to look up every time: kubectl (logs, exec, describe, rollout restart, decoding secrets), helm (values, manifest, history, rollback, diff), docker (volumes, networks, prune, compose), and flux (reconcile, suspend/resume, error logs) — each one prompting for the namespace, pod, or release via a live kubectl/helm query instead of a hardcoded example.

herdr: where the agents live#

herdr is a terminal multiplexer designed for running coding agents. It does what tmux and Zellij do — persistent server, detach/attach, workspaces, tabs, splits — but it also knows which panes are running an agent (Claude Code, Codex, Gemini, pi, opencode and a long list of others) and what state each one is in: working, blocked waiting for input, done, idle. With two or three Claude sessions running across different repos, the question is never “where is my shell?”, it’s “which agent is waiting for me?”.

It’s installed via mise like everything else, and configured in dot_config/herdr/config.toml.

The sidebar#

The left sidebar is the core of the UI. It has two sections:

  • Spaces (workspaces) — one per project, each showing a state icon, the workspace name, and below it the git branch and status.
  • Agents — every agent across all workspaces, grouped by space (agent_panel_sort = "spaces"), with status_indicators = "symbols" so blocked/working/done are distinct glyphs instead of colored dots I can’t tell apart at a glance.

For Claude I override the row layout to show the terminal title too — Claude Code puts a short summary of the current task in the terminal title, so the sidebar effectively becomes a live list of what each agent is doing.

Notifications#

When an agent in a background workspace finishes or needs attention, herdr sends a toast. I set delivery = "system", so it goes straight to the desktop notification service — I can be in a browser and still know Claude is waiting on a permission prompt.

Keybindings#

The prefix is the default Ctrl+b, so tmux muscle memory carries over. On top of that:

BindingAction
prefix+n / prefix+tNew workspace / new tab (no name prompt for tabs)
prefix+ctrl+up/downPrevious / next workspace
prefix+ctrl+left/rightPrevious / next tab
prefix+shift+up/downPrevious / next agent
prefix+1..9Focus agent N
prefix+alt+1..9Switch to workspace N

Navigation is agent-first: numbers jump to agents. Workspaces and tabs are just containers; the agents are what I’m switching between.

Neovim integration: herdr-nvim#

Without a fixed Neovim layout, the editor needed a new home. herdr-nvim solves that in two halves:

  • A herdr plugin, installed with herdr plugin install ChmaraX/herdr-nvim, that adds a full-height Neovim sidebar. prefix+e toggles it: the current panes shift into the left half, nvim takes the right, and toggling off restores the original layout. Each tab keeps its own persistent nvim, so buffers and cursor survive the toggle. prefix+o opens a fuzzy file picker that starts from the files the agent touched most recently, with diff stats. File paths in agent output also become clickable and open in the sidebar.
  • A Neovim plugin (dot_config/nvim/lua/plugins/herdr-nvim.lua, just { "ChmaraX/herdr-nvim", opts = {} }) for annotations: comment on lines or a selection like a code review, then send all the comments to any agent in the workspace with file:line and git context.

The herdr side is installed by a chezmoi script, run_onchange_after_setup-herdr.sh: it runs mise install herdr, then herdr plugin install for every plugin in its list that herdr plugin list doesn’t show yet. chezmoi runs it on the first apply and again only when the script changes — so adding a plugin means adding one line to the list.

Claude Code side#

herdr detects Claude out of the box, but session resume needs Claude to report its session ID. That’s done by a SessionStart hook that runs ~/.claude/hooks/herdr-agent-state.sh, a script herdr generates and maintains. Both the hook entry in settings.json and the script are written by herdr integration install claude, which the same chezmoi script runs right after the plugins — along with herdr --skill, which regenerates the herdr skill for Claude Code so it always matches the installed version.

Claude Code#

Claude Code is Anthropic’s CLI for Claude and a permanent fixture in my workflow — today it runs in herdr panes, often several at once. Its whole config is in the repo under dot_claude/:

  • CLAUDE.md — global instructions: do only what’s asked, keep diffs minimal, ask before mutating commands, state the kube context or Terraform workspace before touching anything, never print secrets.
  • settings.json — auto permission mode with an allowlist of read-only commands (kubectl get/describe/logs, helm template/lint, flux get/logs, shellcheck…), a confirmation prompt on every git push, and a hard deny for container escalation. It’s tracked as create_settings.json: chezmoi writes it only if it doesn’t exist yet, because both herdr (the hook above) and Claude Code itself (/config, “always allow” on a permission) edit it afterwards, and a plain tracked file would keep fighting them.
  • agents/ and skills/.

Conclusion#

A good dotfiles setup is invisible when it works — you sit down at a new machine and it just feels like home. chezmoi handles the mechanics, mise keeps the tooling current, Fish + starship keep the shell fast and informative. What changed this year is the center of gravity: the terminal is no longer organized around the editor, but around the agents — and herdr is the piece that made that shift feel natural instead of chaotic.
